GUIA DE TESTES — DAD | GRUPO 20 | REQUISITO R1
================================================
Projeto: DAD_Grupo20_R1
Tecnologias: Laravel, Laravel Sanctum, SQLite, Docker e Kubernetes
Objetivo: demonstrar o login, a consulta do utilizador, o logout e a
invalidação/expiração do token.

IMPORTANTE
----------
- Os comandos seguintes destinam-se ao PowerShell do Windows, no VS Code.
- Utilizar apenas a conta de demonstração; não introduzir palavras-passe pessoais.
- Não partilhar tokens, APP_KEY ou ficheiros .env.
- A VPN da ESTG é necessária para aceder ao cluster, caso estejas fora da rede.
- Um pedido HTTP 401 após o logout é o resultado CORRETO.
- Para os testes de autenticação, usar /api/auth/login (POST) e não o navegador.


1. TESTAR O PROJETO LOCALMENTE (SEM VPN)
======================================
Abrir o projeto DAD_Grupo20_R1 no VS Code e, no terminal, entrar em backend:

    cd backend

Caso o projeto ainda não esteja preparado:

    composer install
    Copy-Item .env.example .env

No ficheiro .env definir DB_CONNECTION=sqlite, DEMO_EMAIL e DEMO_PASSWORD.
Em seguida, se ainda não tiverem sido executados:

    php artisan key:generate
    New-Item -ItemType File database/database.sqlite -Force | Out-Null
    php artisan migrate --seed

Iniciar o servidor:

    php artisan serve

Manter esse terminal aberto. Noutro terminal PowerShell, verificar:

    Invoke-WebRequest http://127.0.0.1:8000/up -UseBasicParsing

RESULTADO ESPERADO: StatusCode : 200


2. TESTES AUTOMÁTICOS DO R1
==========================
Na pasta backend, executar:

    php artisan test --filter=R1AuthenticationTest

O ficheiro tests/Feature/R1AuthenticationTest.php verifica:
- Bloqueio da consulta sem autenticação (401).
- Rejeição de uma palavra-passe incorreta (422).
- Login com obtenção de token.
- Consulta dos dados do utilizador com token válido (200).
- Logout e invalidação do token (204 e, depois, 401).
- Expiração do token (simulada no teste automático).
- Compatibilidade com /api/login, /api/users/me e /api/logout.

RESULTADO ESPERADO: testes com estado PASS e sem falhas.
NOTA: o teste de expiração simula um token expirado; não implica esperar 1 hora.

5. LOGIN + CONSULTA + LOGOUT + ERRO 401 (COM VPN)
================================================
Executar OS COMANDOS NA MESMA JANELA DO POWERSHELL para manter as variáveis.

5.1. Definir os dados da conta de demonstração

    $url = "http://api-dad-group-20-172.22.21.253.sslip.io"
    $email = "teste@example.test"
    $password = Read-Host "Palavra-passe da conta de demonstracao"

Se o email da conta do cluster for diferente, alterar $email.

5.2. Efetuar login

    $body = @{ email = $email; password = $password } | ConvertTo-Json
    $resposta = Invoke-RestMethod `
        -Uri "$url/api/auth/login" `
        -Method POST `
        -ContentType "application/json" `
        -Headers @{ Accept = "application/json" } `
        -Body $body
    $token = $resposta.token
    if ($token) { Write-Host "LOGIN OK - Token recebido" }

RESULTADO ESPERADO: LOGIN OK - Token recebido.
Não imprimir nem partilhar o valor de $token.

5.3. Consultar o utilizador autenticado

    Invoke-RestMethod `
        -Uri "$url/api/auth/me" `
        -Method GET `
        -Headers @{ Authorization = "Bearer $token"; Accept = "application/json" }

RESULTADO ESPERADO: dados id, name e email; HTTP 200.
A palavra-passe NÃO deve ser devolvida.

5.4. Efetuar logout

    $logout = Invoke-WebRequest `
        -Uri "$url/api/auth/logout" `
        -Method POST `
        -Headers @{ Authorization = "Bearer $token"; Accept = "application/json" } `
        -UseBasicParsing
    Write-Host "Logout HTTP:" $logout.StatusCode

RESULTADO ESPERADO: Logout HTTP: 204.
Uma resposta vazia neste caso é normal.

5.5. Confirmar que o token já não funciona

    try {
        Invoke-WebRequest `
            -Uri "$url/api/auth/me" `
            -Method GET `
            -Headers @{ Authorization = "Bearer $token"; Accept = "application/json" } `
            -UseBasicParsing -ErrorAction Stop | Out-Null
        Write-Host "ATENCAO: o token ainda foi aceite!"
    } catch {
        $codigo = [int]$_.Exception.Response.StatusCode
        Write-Host "Estado HTTP apos logout:" $codigo
    }

RESULTADO ESPERADO: Estado HTTP apos logout: 401.
Este 401 indica que o token foi invalidado corretamente.


6. TESTES NEGATIVOS
===================
6.1. Aceder ao utilizador sem token

    try {
        Invoke-WebRequest "$url/api/auth/me" `
            -Headers @{ Accept = "application/json" } `
            -UseBasicParsing -ErrorAction Stop | Out-Null
    } catch {
        Write-Host "Sem token HTTP:" ([int]$_.Exception.Response.StatusCode)
    }

RESULTADO ESPERADO: 401.

6.2. Login com palavra-passe errada

    $bodyErrado = @{ email = $email; password = "PALAVRA_PASSE_INCORRETA" } | ConvertTo-Json
    try {
        Invoke-WebRequest "$url/api/auth/login" -Method POST `
            -ContentType "application/json" `
            -Headers @{ Accept = "application/json" } `
            -Body $bodyErrado -UseBasicParsing -ErrorAction Stop | Out-Null
    } catch {
        Write-Host "Password incorreta HTTP:" ([int]$_.Exception.Response.StatusCode)
    }

RESULTADO ESPERADO: 422.
NOTA: a rota de login tem limite de 5 pedidos por minuto.
Se forem feitos muitos pedidos seguidos, poderá surgir 429 (Too Many Requests).


7. ALTERNATIVA: TESTAR POR PORT-FORWARD
======================================
Se quiseres testar sem passar pelo Ingress, abrir um terminal e executar:

    $env:KUBECTL_PORT_FORWARD_WEBSOCKETS = "false"
    kubectl -n dad-group-20 port-forward deployment/backend-r1 18002:8000

Manter o terminal aberto. Noutro terminal, executar:

    Invoke-WebRequest http://127.0.0.1:18002/up -UseBasicParsing

RESULTADO ESPERADO: StatusCode : 200.

Se funcionar, repetir os testes do ponto 5, substituindo apenas a linha:

    $url = "http://127.0.0.1:18002"

Se surgir 'lost connection to pod', utilizar o Ingress do ponto 4.
A variável acima pode não ter efeito em todas as versões do kubectl.

RESUMO DOS CÓDIGOS HTTP
-----------------------
200 = Pedido executado com sucesso.
204 = Logout realizado, sem conteúdo na resposta.
401 = Não autenticado / token inválido ou revogado.
422 = Credenciais inválidas ou erro de validação.
429 = Número excessivo de pedidos.
500 = Erro interno do servidor (verificar os logs do Laravel).
